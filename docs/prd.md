# 手势桌面交互产品 PRD

> 文档版本：v0.3  
> 创建日期：2026-05-21  
> 文档语言：中文  
> 当前阶段：Phase 1.5 工程验证原型，重点验证相对移动、舒适区、clutch 和边缘巡航  
> 项目代号：New Interaction

## 1. 产品一句话

New Interaction 是一个基于电脑摄像头的手势输入层，让用户通过自然手势完成鼠标移动、单击、双击、拖拽、滚动等基础桌面操作。短期它是鼠标和触控板的辅助输入方式，长期目标是形成可大规模商用的手势识别系统，完全替代传统鼠标，成为桌面环境中的新一代自然交互范式。

## 2. 背景与机会

传统鼠标和触控板是高精度、低成本、低学习成本的输入设备，但它们要求用户持续接触硬件。对于演示、投屏、大屏控制、临时手部不便、腕部疲劳等场景，鼠标并不是最自然的输入方式。

Vision Pro 证明了“视觉注意力 + 简单手势确认”可以成为一种高质量交互范式。但本产品不复制 Vision Pro 的眼动交互，不假设用户拥有头显、深度相机或系统级空间计算能力。我们聚焦在普通电脑摄像头能够稳定获得的信号：手部姿态、手指关键点、手掌运动轨迹和手势状态。

产品机会不在于第一版就完整替代鼠标，而在于先提供一个可靠的“手势鼠标层”，让用户在真实桌面任务中建立信任；随后通过屏幕语义、状态化光标、跨应用适配和个性化配置，把手势输入从辅助能力推进为主力输入方式。

## 3. 产品目标

### 3.1 近期目标

在普通笔记本或外接摄像头环境下，让用户可以通过单手完成基础鼠标操作：

- 移动鼠标指针
- 左键单击和双击
- 按住拖拽
- 上下左右滚动
- 暂停与恢复识别
- 调整灵敏度和惯性

### 3.2 中期目标

围绕高价值场景形成可感知的产品体验：

- 演示模式：控制 PPT、Keynote、浏览器页面和白板
- 远距离模式：在投屏、大屏、沙发等场景中控制电脑
- 辅助模式：降低鼠标使用频率，服务手腕疲劳或临时行动不便用户
- 应用配置：为浏览器、演示软件、白板工具提供不同手势映射

### 3.3 长期目标

从“摄像头手势鼠标”演进为“桌面自然交互层”，长期替代鼠标在日常桌面操作中的位置：

- 结合系统无障碍接口理解当前屏幕控件
- 对按钮、输入框、窗口边缘等目标做吸附和容错
- 用状态化光标表达移动、按下、拖拽、滚动、暂停等输入状态
- 支持用户自定义手势与应用级快捷动作
- 建立手势意图识别模型，让系统识别“用户想做什么”，而不只是识别“手指在哪里”
- 形成可跨用户、跨光照、跨摄像头、跨姿势稳定运行的商用级识别能力

## 4. 非目标

当前阶段不追求以下能力：

- 不做眼动追踪
- 不做完整 Vision Pro 交互复刻
- 不做 VR/AR 空间界面
- 不做全手势操作系统
- MVP 不承诺完全替代鼠标、触控板或键盘
- 不上传摄像头画面到云端
- 不在 MVP 中支持复杂多手组合手势

## 5. 目标用户

### 5.1 演示者

典型场景：会议室、教室、直播、录屏。  
核心诉求：离开键盘鼠标后仍能控制页面、切换内容、点击按钮。  
成功标准：不需要额外遥控器，手势控制稳定，不在观众面前误触。

### 5.2 大屏/远距离用户

典型场景：Mac 连接电视、投影、外接大屏。  
核心诉求：坐在较远位置也能完成点击、滚动、播放、暂停等操作。  
成功标准：不需要频繁走回电脑旁边，基础操作可以顺畅完成。

### 5.3 鼠标疲劳用户

典型场景：长时间办公、手腕疲劳、临时无法舒适使用鼠标。  
核心诉求：减少鼠标依赖，用另一种方式完成低频操作。  
成功标准：手势输入能作为补充，而不是制造新的疲劳。

### 5.4 技术探索用户

典型场景：开发者、设计师、交互研究者。  
核心诉求：体验新的输入范式，配置和扩展手势能力。  
成功标准：产品足够透明，可调参，可观察手势状态。

## 6. 核心使用场景

### 6.1 基础桌面控制

用户打开应用，授权摄像头和系统辅助功能权限。应用识别用户单手姿态，将食指或手掌中心映射为屏幕指针位置。用户通过捏合、保持捏合、移动手掌等动作完成点击、拖拽和滚动。

### 6.2 演示控制

用户进入演示模式。系统降低高精度鼠标移动需求，优先识别上一页、下一页、点击、滚动、激光指示等动作。演示模式要求更低误触、更强状态反馈，而不是最高自由度。

### 6.3 远距离浏览

用户坐在距离屏幕 1-3 米的位置，通过手势控制浏览器、视频播放器或网页。系统使用更强的平滑、吸附和大目标交互策略，减少小幅抖动带来的困扰。

### 6.4 辅助输入到主力输入

短期用户不需要完全放弃鼠标，而是在部分时刻切换到手势控制。产品需要提供清晰的开关、暂停手势和键盘快捷键，让用户可以随时恢复传统输入。长期产品应逐步覆盖鼠标的主要能力，并通过更自然的状态反馈和屏幕语义能力，让手势成为用户愿意长期依赖的主力输入方式。

## 7. MVP 功能范围

### 7.1 摄像头与手部识别

- 调用本地摄像头
- 实时检测单手 21 个关键点
- 识别左右手
- 显示当前识别状态
- 在识别丢失时自动暂停鼠标事件注入

### 7.2 鼠标移动

- 默认使用食指指尖作为指针控制点
- 支持坐标映射到整块屏幕
- 工程验证早期可保留绝对坐标映射作为调试模式
- 产品默认移动方式应逐步转向相对移动：手部位移驱动鼠标增量，而不是食指位置直接等于屏幕坐标
- 支持舒适区：用户只需要在自然、低负担的小范围内移动手，即可控制整块屏幕
- 支持 clutch 重定位：用户可以临时脱离鼠标移动，把手放回舒适区后继续控制，类似抬起鼠标重新放回鼠标垫或触控板手指抬起再滑
- 提供移动平滑，降低抖动
- 提供灵敏度调节
- 提供动态增益：慢速移动时便于精确定位，快速移动时可以跨越大屏幕距离
- 提供边缘巡航：手指保持在舒适区边缘时，指针持续向对应方向移动，降低大屏边缘不可达问题
- 支持边界限制，避免指针飞出可视区域

### 7.3 点击

- 默认手势：拇指与食指捏合
- 捏合进入“按下”状态
- 松开进入“释放”状态
- 短暂捏合一次识别为左键单击
- 在双击时间窗口内快速短暂捏合两次识别为左键双击
- 单击、双击和拖拽需要通过状态机区分，避免一次长按被误判为双击
- 提供点击节流和双击时间窗口配置，降低连续误触

### 7.4 拖拽

- 用户捏合并保持超过短阈值后进入拖拽状态
- 拖拽期间手部移动映射为鼠标拖动
- 松开捏合结束拖拽
- 拖拽状态需要通过状态化光标或轻量状态提示明确表达

### 7.5 滚动

- 默认手势：食指和中指伸出形成“双指滚动模式”，拇指不参与捏合
- 进入双指滚动模式后，手部上下移动映射为垂直滚动，左右移动映射为水平滚动
- 滚动模式下暂停鼠标指针移动，避免用户想滚动时同时移动光标
- 捏合手势只负责点击和拖拽，不承担滚动，避免与上下拖拽产生意图冲突
- 支持滚动速度调节
- 支持自然滚动方向配置
- MVP 支持垂直滚动；工程验证阶段同步探索水平滚动，产品目标是上下左右滚动都使用同一套无冲突手势

### 7.6 暂停与恢复

- 默认手势：张开手掌保持短时间，切换暂停/恢复
- 提供键盘快捷键作为可靠兜底
- 暂停状态不注入任何鼠标事件
- 暂停状态通过状态化光标、状态栏图标或轻量提示持续可见

### 7.7 设置

- 摄像头选择
- 控制手选择：左手、右手、自动
- 指针灵敏度
- 平滑强度
- 点击阈值
- 拖拽触发时间
- 滚动速度
- 启动后是否自动启用识别

## 8. 推荐手势映射

| 用户手势 | MVP 行为 | 设计理由 |
| --- | --- | --- |
| 食指移动 | 移动鼠标 | 直觉强，易教学 |
| 拇指食指短捏合一次 | 左键单击 | 与 Vision Pro 的捏合确认类似，学习成本低 |
| 拇指食指快速短捏合两次 | 左键双击 | 保留桌面鼠标的核心操作能力 |
| 拇指食指捏住并移动 | 拖拽 | 与鼠标按住拖拽一致 |
| 食指中指伸出并移动 | 上下左右滚动 | 与捏合拖拽解耦，避免意图冲突 |
| 张开手掌保持 | 暂停/恢复 | 与“停止输入”的语义接近 |
| 中指捏合或双指捏合 | 右键，后续版本支持 | MVP 可先不开放，避免误触 |

## 9. 交互原则

### 9.1 少手势，高可靠

MVP 中宁可少做手势，也要让每个手势稳定。用户对输入设备的容错极低，误触一次的破坏感大于少一个功能的遗憾。

### 9.2 状态必须可见

用户需要随时知道系统处于什么状态。优先方向不是常驻一个笨重控制面板，而是革新桌面光标样式：用不同图案、颜色或动效表达当前输入状态，让用户看鼠标指针本身就能理解系统正在做什么。

- 未检测到手
- 已检测到手
- 可移动
- 按下中
- 单击确认
- 双击确认
- 拖拽中
- 滚动中
- 已暂停

### 9.3 支持自然借力姿势

产品不需要过度限制用户姿势。用户会自然找到舒服的控制方式，例如把大臂架在桌上，用小臂和手腕完成移动。产品需要保证在这类低负担姿势下仍能稳定识别，而不是要求用户用夸张、标准化或长期悬空的动作来适配系统。

### 9.4 传统输入永远可接管

鼠标、触控板和键盘始终保留最高优先级。手势系统不能阻止用户用传统方式纠错。

### 9.5 本地处理优先

摄像头画面只在本机实时处理，不上传、不保存。当前阶段不采集诊断数据，也不记录可还原用户行为的手势轨迹。

### 9.6 小范围驱动大屏幕

产品不应要求用户用手在空气中覆盖整块屏幕。尤其在外接大屏、投影、远距离控制和用户大臂架桌的舒适姿势下，手部自然可动范围远小于屏幕范围。因此，默认交互应从“绝对位置映射”逐步升级为“相对移动 + 舒适区 + 动态增益”的手势触控板模型。

舒适区指用户在当前坐姿下，手可以低负担、可重复移动的一小块空间，而不是摄像头画面的固定中心区域。系统可以先自动以用户当前稳定食指位置为中心生成舒适区，后续再提供手动校准，让用户自然移动到上下左右仍然舒服的边界。

重定位行为使用 clutch 状态实现：在 `active_move` 状态下，手指移动会驱动鼠标；在 `clutch` 状态下，用户可以移动手但鼠标不动；回到 `active_move` 时，系统把当前食指位置设为新的参考点，继续用相对位移控制鼠标。推荐触发方式是“食指明确伸出 = 控制，食指收回或手自然放松 = clutch”，避免和张开手掌暂停、捏合点击、双指滚动冲突。

## 10. 产品形态

### 10.1 MVP 形态

推荐先做后台常驻的本地输入工具，优先支持 macOS。它不应该是一个需要长期停留在前台的完整 App 页面，而应该像输入法或系统输入增强工具一样默默运行：

- 菜单栏常驻
- 默认后台运行，不占用 Dock 或只保留极轻入口
- 状态栏图标展示启用、暂停、错误等状态
- 设置面板只在用户主动打开时出现
- 工程验证阶段提供摄像头预览和手部关键点调试视图，正式使用时默认隐藏
- 状态化光标表达移动、点击、拖拽、滚动、暂停等核心状态
- 系统辅助功能权限引导
- 一键启用/暂停

### 10.2 为什么不是浏览器插件

浏览器插件只能控制网页内部行为，无法完整替代鼠标事件，也难以覆盖桌面、演示软件和系统窗口。它适合后续做网页增强，不适合作为核心产品形态。

### 10.3 为什么不是移动 App

移动 App 可以把手机当摄像头或遥控器，但会引入第二设备，削弱“电脑摄像头即输入设备”的产品表达。它可以作为后续补充，不适合作为第一阶段主路径。

## 11. 技术实现原则

### 11.1 当前原型

当前原型使用 Python 快速验证：

- OpenCV 调用摄像头
- MediaPipe Hand Landmarker 做手部关键点检测
- PyAutoGUI 或系统事件接口注入鼠标事件
- 简单窗口显示状态和调参

这个阶段目标是验证手势映射、误触控制、延迟和疲劳感，不追求产品级 UI。

### 11.2 产品化方向

当核心交互可用后，再迁移到 macOS 原生或跨平台桌面应用：

- macOS 原生方向：Swift、AVFoundation、Vision/Core ML 或 MediaPipe、Quartz 事件注入
- 跨平台方向：Tauri 或 Electron 作为 UI，Rust/Swift/Objective-C/平台原生模块负责摄像头和鼠标事件

### 11.3 算法策略

核心不只是“识别手”，而是把识别结果变成稳定输入：

- 关键点滤波，减少抖动
- 手势状态机，避免瞬时误判
- 坐标映射校准，适应不同摄像头角度
- 点击冷却，避免重复点击
- 丢帧容错，避免识别短暂消失导致拖拽中断
- 置信度阈值，低质量识别时暂停操作

### 11.4 商用级识别架构

当前工程验证版本使用“手部关键点 + 几何规则”判断手势。这适合验证摄像头、关键点追踪和鼠标事件注入，但不适合作为最终商用识别系统。商用版本需要把“姿态识别”升级为“意图识别”，采用三层架构：

1. 手部追踪层：使用成熟手部检测和关键点追踪模型，输出手部 21 个关键点、左右手、置信度和基础时序信息。优先使用 MediaPipe Hand Landmarker、Apple Vision 或后续等价的端侧模型，不在早期自研底层手部追踪模型。
2. 手势意图识别层：基于关键点序列训练轻量模型，判断用户当前意图，例如无动作、移动、捏合候选、单击、双击、拖拽、滚动、暂停。输入包括过去若干帧的关键点、关键点速度、手型变化、左右手、置信度和当前状态机上下文。
3. 交互安全层：用状态机、阈值、冷却时间、右手过滤、低置信度保护、传统输入接管等规则做安全边界。模型负责判断概率，规则负责防止误触和失控。

模型训练路线不应从原始图像直接预测鼠标动作开始。第一阶段更适合训练“基于手部关键点时序的意图识别模型”，因为它数据成本更低、端上实时性更好、隐私风险更小、错误更容易调试。只有当关键点模型无法可靠区分真实捏合接触、遮挡或复杂姿态时，再补充小型图像 patch 模型或端到端视觉模型。

### 11.5 商用稳定性要求

商用阶段的核心标准不是“能识别手势”，而是“长期使用时不会让用户失去控制感”。系统需要满足：

- 误触率足够低，尤其是点击、双击、拖拽这类破坏性操作
- 所有动作都有明确状态反馈，用户能知道系统为什么正在移动、点击、拖拽或暂停
- 识别只在可信状态下生效，低置信度、非目标手、遮挡、多人入镜时默认不触发操作
- 传统鼠标、触控板和键盘始终可以接管
- 用户可以快速暂停、恢复、重置映射和校准
- 不同用户、手型、肤色、光照、背景、摄像头角度下保持稳定

## 12. 数据与隐私

### 12.1 默认数据策略

- 摄像头画面只在本机处理
- 不保存原始视频
- 不上传图像或关键点
- 默认不采集个人身份信息

### 12.2 诊断数据边界

当前阶段不允许采集、上传或保存诊断数据。所有识别、状态判断和鼠标事件注入都只在本地运行。

后续如果进入公开测试和模型训练阶段，需要单独设计用户主动同意的数据闭环。优先采集本地生成的关键点序列、手势标签、模型置信度和状态机结果，而不是原始视频。即使未来加入诊断，也只能考虑记录：

- 平均帧率
- 平均识别延迟
- 手势触发次数
- 识别丢失次数
- 用户主动撤销或暂停次数
- 设备型号和摄像头分辨率
- 用户主动标注的手势类型
- 经过脱敏和裁剪的关键点时序样本

诊断数据默认不应包含视频帧、截图、音频或可还原个人行为的内容。若未来确实需要原始视频或图像 patch 用于模型训练，必须单独申请明确授权，提供本地预览、删除能力和退出机制。

## 13. 成功指标

### 13.1 MVP 可用性观察指标

当前阶段成功标准以用户反馈为主，以下指标用于工程自测和体验观察，不作为硬性上线门槛。

- 首次完成摄像头和权限配置时间小于 2 分钟
- 从启动到识别到手的时间小于 3 秒
- 指针移动端到端延迟目标小于 100ms
- 常规光照下连续识别 10 分钟无崩溃
- 10 分钟基础操作中误点击不超过 3 次
- 用户可以在 1 分钟内学会移动、点击、暂停

### 13.2 产品体验指标

- 演示模式下翻页和点击成功率高于 95%
- 用户主观疲劳评分低于传统长时间悬空操作
- 暂停/恢复操作成功率高于 98%
- 用户愿意在至少一个真实场景中重复使用

### 13.3 商用识别指标

进入商用阶段前，需要建立更严格的识别指标：

- 非意图点击误触率接近零，点击类动作必须优先保守
- 连续 1 小时使用不出现无法恢复的拖拽、按下或暂停状态
- 右手过滤、低置信度保护和多人入镜保护稳定生效
- 常见光照、摄像头角度和桌面姿势下移动、点击、拖拽、滚动均可复现
- 关键点意图模型在离线验证集、真实用户试用和长时间在线试用中表现一致
- 模型推理和事件注入不破坏端到端延迟目标

## 14. 风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 摄像头角度差异大 | 指针映射不稳定 | 提供校准流程和灵敏度设置 |
| 光照差导致识别失败 | 使用中断 | 给出状态提示，低置信度时暂停注入 |
| 手部抖动导致误触 | 用户失去信任 | 平滑、阈值、状态机、冷却时间 |
| 姿势适配不足 | 用户找不到舒服的操作姿势 | 支持大臂架桌、小臂移动等自然借力姿势 |
| 系统权限配置复杂 | 新手流失 | 做清晰权限引导和检测 |
| 鼠标注入影响正常操作 | 破坏安全感 | 保留快捷键暂停、传统输入接管、状态可见 |
| 普通摄像头不支持精细空间深度 | 手势表达受限 | 少手势、单手为主，后续再扩展多模态 |
| 纯几何规则无法覆盖用户差异 | 商用稳定性不足 | 逐步引入关键点时序意图模型，并保留规则安全层 |
| 模型误判用户意图 | 造成误触或失控 | 模型只给出概率，交互状态机负责最终触发条件 |
| 训练数据隐私敏感 | 用户信任受损 | 优先采集关键点序列和本地标注，原始视频单独授权 |

## 15. 迭代路线图

### Phase 0：技术验证

目标：证明“摄像头手势可以稳定控制鼠标”。

范围：

- 摄像头调用
- 单手关键点检测
- 指针移动
- 捏合单击和双击
- 基础拖拽
- 双指模式基础滚动
- 控制台或简单窗口显示状态

交付标准：

- 能在本机完成浏览器打开链接、双击打开目标、拖动窗口、滚动网页
- 能清楚观察识别状态和鼠标事件状态
- 能记录主要问题：延迟、抖动、误触、疲劳

### Phase 1：规则增强与误触控制

目标：把工程验证脚本从“能动”提升到“可控”，解决当前误触和失控问题。

范围：

- 只识别右手，非目标手默认忽略
- 捏合从单帧距离判断升级为严格状态机
- 捏合必须经过打开、靠近、接触、释放过程
- 点击、双击、拖拽、滚动、暂停状态互斥，避免意图冲突
- 增加 hysteresis：进入阈值和释放阈值分离
- 释放判断必须足够敏捷，尤其是拖拽结束时需要立即松开系统鼠标按下状态
- 指针移动和拖拽移动增加轨迹平滑，降低关键点抖动，但平滑不得延迟点击和释放判断
- 手部尺度估计需要尽量抗姿态变化，不能只依赖单根手指长度，应结合掌宽、掌心/手腕等稳定关键点
- 增加连续帧确认，低置信度和遮挡时不触发操作
- 增加实时状态日志和调试 HUD，解释系统为什么触发或不触发

交付标准：

- 左手摸脸、路过画面、短暂遮挡不触发鼠标操作
- 捏合误触明显下降，点击类操作默认保守
- 捏合释放后拖拽能即时停止，不出现窗口继续跟随手势移动
- 食指移动和拖拽移动的抖动明显下降，同时保留可接受的跟手性
- 常见手腕旋转、手掌倾斜和手离摄像头远近变化下，基础捏合识别不明显劣化
- 用户能通过状态反馈理解当前处于移动、候选捏合、点击、拖拽、滚动还是暂停
- 真实鼠标接管后，手势输入可以恢复到可预测状态

### Phase 1.5：大屏映射与舒适区交互

目标：解决大屏和外接显示器下“手部自然移动范围不足以覆盖整块屏幕”的问题，把鼠标移动从绝对坐标映射升级为更适合长期使用的手势触控板模型。

问题定义：

- 绝对映射会把摄像头画面中的食指位置直接映射到屏幕位置
- 屏幕越大、摄像头视角越窄、用户姿势越舒适，越容易出现屏幕边缘够不到
- 单纯提高灵敏度会放大抖动，降低点击精度，无法同时满足大范围移动和精准定位

范围：

- 保留绝对坐标映射作为调试模式，不作为长期默认体验
- 新增相对移动模式：鼠标移动量来自食指相对上一参考点的位移
- 新增舒适区概念：以用户自然中立手位为中心，定义一块可低负担、可重复移动的控制区域
- MVP 先支持自动舒适区：首次检测到稳定右手后，以当前食指位置生成默认控制区
- 后续支持手动舒适区校准：用户自然向左、右、上、下移动到仍然舒服的边界，系统记录控制范围
- 新增 clutch 重定位状态：用户可以移动手但不移动鼠标，重新把手放回舒适区后继续控制
- 推荐 clutch 触发方式：食指明确伸出进入 `active_move`，食指收回或手自然放松进入 `clutch`
- clutch 不使用张开手掌，避免和暂停/恢复手势冲突
- 新增动态增益：慢速移动低增益，优先精确；快速移动高增益，优先跨屏
- 新增边缘巡航：手指持续靠近舒适区边缘时，鼠标持续向对应方向移动，直到手回到舒适区中部或进入 clutch
- 对当前模式提供状态反馈，让用户知道系统处于 `active_move`、`clutch`、边缘巡航还是暂停

交互状态：

- `active_move`：食指明确伸出，手部相对位移驱动鼠标
- `clutch`：食指收回或手自然放松，用户可以重置手位，鼠标保持不动
- `edge_cruise`：食指保持在舒适区边缘，鼠标持续向边缘方向移动
- `paused`：张开手掌保持触发暂停，不注入任何输入事件

交付标准：

- 用户不需要把手移动到摄像头画面边缘，也能把鼠标移动到屏幕四角
- 用户可以像抬起鼠标重新放回鼠标垫一样，把手放回舒适区且鼠标不跳动
- 大范围移动和小目标点击可以共存，不依赖单一高灵敏度
- 在外接大屏或高分辨率屏幕下，鼠标边缘到达能力明显提升
- 新模式不破坏点击、拖拽、滚动和暂停的既有手势语义

### Phase 2：本地数据闭环与关键点数据集

目标：为商用级手势意图识别建立训练数据基础，同时保持隐私优先。

范围：

- 本地记录用户主动同意的关键点时序样本
- 支持用户标注或确认动作标签：无动作、移动、点击、双击、拖拽、滚动、暂停
- 记录状态机判断、置信度、触发结果和用户纠错行为
- 默认不保存原始视频，不上传数据
- 提供样本预览、删除和导出能力
- 建立离线评测集，覆盖不同用户、光照、摄像头角度和操作姿势

交付标准：

- 能采集一批可复现的关键点时序样本
- 每条样本可以追溯到动作标签和状态机结果
- 用户能清楚知道采集了什么，并能删除
- 建立首版误触、漏触、延迟和稳定性评测基线

### Phase 3：关键点时序意图模型

目标：从纯规则识别升级为“模型判断意图 + 规则保证安全”的混合识别系统。

范围：

- 训练基于 21 个关键点时序的轻量模型
- 输入包含关键点位置、速度、左右手、置信度和状态机上下文
- 输出包含无动作、移动、捏合候选、单击、双击、拖拽、滚动、暂停等意图概率
- 模型推理在本机端侧运行
- 状态机仍作为最终触发门槛，避免模型直接控制鼠标
- 提供模型版本、回滚和 A/B 评测机制

交付标准：

- 在离线评测集上，意图识别明显优于纯规则
- 在真实试用中，点击误触和滚动/拖拽冲突显著下降
- 模型推理不破坏端到端延迟目标
- 出现低置信度或模型不确定时，系统默认不触发高风险动作

### Phase 4：屏幕语义增强

目标：降低手势精度要求，让系统理解当前屏幕对象，从“移动鼠标”走向“操作目标”。

范围：

- 读取当前窗口和可交互控件
- 对按钮、输入框、菜单项做吸附
- 支持大目标优先、小目标放大确认
- 根据应用类型调整交互策略
- 结合状态化光标展示当前可交互目标

交付标准：

- 小按钮点击成功率明显提升
- 用户需要的手部精度降低
- 产品从“模拟鼠标”开始接近“理解操作意图”

### Phase 5：MVP 桌面应用

目标：形成可给真实用户长期试用的后台输入工具。

范围：

- macOS 桌面应用或包装后的桌面程序
- 菜单栏入口
- 状态栏图标和状态化光标
- 设置面板
- 摄像头与辅助功能权限引导
- 移动、点击、拖拽、滚动、暂停
- 调参能力
- 模型版本与识别模式选择

交付标准：

- 非开发者可以完成安装、授权、启用
- 用户能完成 3 个真实任务：点击网页按钮、拖动窗口、滚动网页
- 误触有明显下降，用户知道如何暂停
- 用户可以在真实工作中连续使用，并通过反馈推动模型和规则迭代

### Phase 6：场景模式与自定义

目标：在稳定通用输入能力上，扩展到不同桌面场景和用户习惯。

范围：

- 演示模式
- 浏览模式
- 视频控制模式
- 白板模式
- 每个模式有独立手势映射、灵敏度和模型阈值
- 快捷键快速切换模式
- 自定义手势和应用级快捷动作
- 用户配置导入导出

交付标准：

- 演示模式可以稳定完成翻页、点击和指示
- 浏览模式可以稳定滚动、点击和返回
- 用户能理解不同模式的差异
- 用户可以为特定应用配置动作

### Phase 7：端到端视觉补充与商用化

目标：补齐关键点时序模型无法解决的边界问题，形成可大规模商用的手势识别系统。

范围：

- 针对真实捏合接触、遮挡、手掌旋转等难例，补充小型图像 patch 模型
- 评估是否需要端到端视觉模型辅助判断复杂意图
- 建立跨设备、跨用户、跨光照的评测体系
- 建立模型训练、发布、回滚、监控流程
- 完善状态化光标、权限引导、安全暂停和异常恢复
- 为 macOS 之外的平台预留摄像头、模型推理和输入注入适配层

交付标准：

- 长时间使用下误触、漏触和失控事件达到商用可接受范围
- 用户可以在主要桌面任务中不依赖传统鼠标完成操作
- 模型和规则系统可持续迭代，不依赖单次手工调参
- 产品具备从辅助输入走向鼠标替代的商业化基础

## 16. 已确认产品决策

以下方向已确认，后续迭代 PRD 时可继续调整：

| 决策项 | 当前建议 | 原因 |
| --- | --- | --- |
| 产品定位 | 短期辅助交互，长期替代鼠标 | 先降低使用门槛，再逐步建立新交互范式 |
| 首发平台 | macOS，架构上预留跨平台边界 | 当前开发环境匹配，权限和桌面事件能力清晰，但不把实现写死在单平台抽象里 |
| MVP 技术路线 | Python 原型先行 | 最快验证手势映射和可用性 |
| 产品化路线 | macOS 后台输入工具 | 更适合权限、状态栏、系统输入层，不需要常驻完整前端 |
| MVP 控制方式 | 单手为主 | 简单、稳定、学习成本低 |
| 默认指针控制点 | 食指指尖 | 直觉最强 |
| 默认指针映射方向 | 从绝对映射逐步升级为相对移动 | 绝对映射在大屏和舒适坐姿下容易够不到边缘，相对移动更接近触控板和鼠标垫体验 |
| 舒适区定义 | 用户自然中立手位附近的低负担可动范围 | 产品应适配用户舒服姿势，而不是要求用户用手覆盖摄像头画面 |
| 重定位交互 | 食指收回或手自然放松进入 clutch | 类似鼠标抬起重新放、触控板手指抬起再滑，且不与张开手掌暂停冲突 |
| 大屏移动策略 | 动态增益 + 边缘巡航 | 同时满足跨屏效率和小目标精度，优于单纯提高灵敏度 |
| 默认点击手势 | 拇指食指短捏合，支持单击和双击 | 易识别，语义接近确认，同时保留桌面核心操作 |
| 默认滚动手势 | 食指中指伸出的双指滚动模式 | 与捏合拖拽解耦，降低冲突 |
| 默认暂停手势 | 张开手掌保持 | 容易理解，适合兜底 |
| MVP 场景 | 基础桌面控制优先 | 先验证鼠标核心能力，再扩展场景 |
| 原型深度 | 先做工程验证脚本 | 尽快验证识别、事件注入和手势冲突 |
| 隐私策略 | 全本地处理，暂不采集诊断数据 | 摄像头产品必须建立信任 |
| 成功标准 | 先看用户反馈 | 当前阶段以真实体验问题驱动迭代 |
| 商用识别路线 | 规则增强 → 关键点时序模型 → 视觉补充 | 先用可解释、低成本、端侧实时的方式建立稳定意图识别 |
